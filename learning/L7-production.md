# L7: 生产落地——测试、安全、可观测性

> 阶段：4（伴随Phase 6）
> 目标：理解Agent系统上线前的关键检查点

## 1. 测试策略

### Agent系统的三层测试

```
E2E测试：     关键用户流程端到端
    ↓
集成测试：     Agent与工具/API的连接
    ↓
单元测试：     每个函数、每个工具的正确性
```

### Agent特有的测试挑战

| 挑战 | 应对 |
|------|------|
| Agent输出不确定 | 不测试具体输出，测试输出是否满足约束（类型正确、值在合理范围） |
| Agent会调用外部服务 | Mock外部工具，验证调用参数是否合法 |
| Agent可能进入死循环 | 加超时限制+最大步数限制 |
| 幻觉内容难以检测 | 对关键字段做规则校验（"日期必须是YYYY-MM-DD格式"） |

### 在Company Mode中

QA Director在Phase 2就制定了测试策略，不是等代码写完才想怎么测。这就是"测试左移"。

## 2. 安全审计

### Agent系统特有的安全风险

| 风险 | 示例 | 防护 |
|------|------|------|
| 提示注入 | 用户输入"忽略之前的指令" | 输入过滤、指令优先级 |
| 工具滥用 | Agent调用危险命令 | 权限控制、沙箱执行 |
| 数据泄露 | Agent把敏感数据输出到日志 | 敏感数据脱敏 |
| 供应链攻击 | 依赖的MCP Server被篡改 | 来源验证、版本锁定 |

### 最小权限原则

每个Agent只给它完成任务所需的最小权限：
- 读文件的Agent → 不给写权限
- 写代码的Agent → 不给删目录的权限
- 查询数据库的Agent → 只读账号

## 3. 可观测性

### 三个核心指标

| 指标 | 含义 | 目标 |
|------|------|------|
| 成功率 | 任务完成/总任务 | >95% |
| 平均步数 | 完成任务需要多少步 | 越少越好，但要稳定 |
| Token效率 | 每个任务平均Token消耗 | 持续下降趋势 |

### 生产监控

- 每个Agent的操作日志（谁、什么时候、做了什么、结果）
- Token消耗趋势（突然升高 → 可能有问题）
- 错误率按Agent分组（快速定位问题Agent）

## 4. CI/CD集成

```
Git Push → CI Pipeline → 测试 → 安全扫描 → 构建 → 部署
```

Agent写代码后的关键步骤：
1. 人工或自动化代码审查
2. 自动化测试（Agent写的测试也要跑）
3. 安全扫描（检查Agent是否引入了漏洞）
4. 构建验证（Agent改的代码能编译/运行吗）

## 深度思考

1. 如果你的Agent系统在上线后发现一个Bug，你怎么判断是Agent的决策错误还是工具本身的问题？
2. "最小权限"原则在Company Mode中是怎么实现的？
3. 当Agent的"成功率"是95%时，剩下的5%由谁兜底？
