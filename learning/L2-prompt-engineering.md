# L2: 提示工程——怎么给AI下好指令

> 阶段：1（伴随Phase 1-2）
> 目标：理解提示工程的核心技巧，能在项目中写出好的提示

## 1. 提示工程的本质

**不是**：学一套魔法咒语让AI听话

**而是**：结构化地传递上下文，消除歧义，让模型精确理解你想要什么

## 2. System Prompt vs User Message

```
┌──────────────────────────┐
│ System Prompt (系统提示)   │  ← "你是谁，规则是什么"
│ 你是一个Python专家...      │     每次会话开头，用户看不到
├──────────────────────────┤
│ User Message (用户消息)    │  ← "做什么"
│ 帮我写一个排序函数         │     用户每次发的内容
└──────────────────────────┘
```

**在Company Mode中**：每个Agent背后都有一个System Prompt定义了它的角色。CEO（我）的System Prompt里写了"第一性原理思考"、"不盲从用户"就是你的 `~/.claude/CLAUDE.md`。

## 3. 五个核心技巧

### 3.1 给上下文，不要只给任务

❌ "帮我写个API"
✅ "帮我写一个用户注册API，框架用FastAPI，数据库用PostgreSQL，需要邮箱验证"

### 3.2 给约束，不要只给目标

❌ "代码要写得好"
✅ "函数不超过30行，嵌套不超过3层，不引入新的依赖"

### 3.3 给例子，不要只给描述

❌ "输出格式要友好"
✅ "输出格式像这样：{status: 'ok', data: {...}, error: null}"

### 3.4 给负面清单，不要只给正面指引

❌ "注意安全"
✅ "不要硬编码密钥、不要拼接SQL、不要信任用户输入"

### 3.5 分步，不要混在一起

❌ "设计一个系统，要能处理用户订单支付退款还要发邮件"
✅ "先设计数据库Schema → 再做订单模块 → 再做支付模块 → 最后做退款"

## 4. 提示工程在Company Mode中的应用

看看我们的攻击DA是怎么给AI下指令的：

```
"从前提假设、替代方案、边界条件、安全风险、成本效率、依赖风险
六个角度质疑这个决策。每个角度必须给出具体论据，不能只说'可能有问题'。"
```

这就是一个好的提示：
- 给了具体维度（6个角度）
- 给了方法（具体论据）
- 给了负面清单（不能只说"可能有问题"）
