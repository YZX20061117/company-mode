# L1: AI基础——LLM、Token、API

> 阶段：0（项目启动前）
> 目标：理解AI编程工具的基本工作原理

## 1. LLM是什么

**本质**：LLM（大语言模型）是一个"下一个词预测器"。你给它一段文字，它预测后面最可能出现的词，一个词一个词地生成。

**类比**：它像一个读过互联网上几乎所有公开文本的人，你问什么它都能接话。但它不是数据库——它是基于概率生成，不是在查答案。

**关键理解**：LLM没有"知道"和"不知道"的明确边界，它只是预测。这是它既强大又危险的根本原因——它会"编造"听起来很合理但完全错误的内容（幻觉）。

## 2. Token是什么

**本质**：Token是LLM处理文本的最小单位。一个中文字通常=1-2个Token，一个英文词=1-3个Token。

**为什么重要**：
- LLM按Token计费（输入+输出都算）
- 每个模型有Context Window上限（一次能处理的最大Token数）
- Claude Code里用 `/cost` 可以看到Token消耗

**体感换算**：这篇L1文档约1500个中文字 ≈ 2500-3000 Tokens

## 3. Context Window

**本质**：模型一次能"看到"的文本总量。

**类比**：它是LLM的"工作记忆"。你和它的所有对话、它读取的文件、它写的代码，都在这一个窗口里。超过上限，最早的内容就会被截断。

**不同模型的Context Window**：
- DeepSeek V4 Pro: 1M tokens（超长，可以一次读整本书）
- Claude Sonnet 4.6: 200K tokens
- GPT-5.5: 256K tokens

**实际意义**：在Company Mode中，这就是为什么CEO（我）要控制每个Phase的讨论深度——因为所有讨论都消耗Context Window。

## 4. API调用是怎么回事

**流程**：
```
你的指令 → HTTP请求 → LLM服务器 → 模型推理 → 返回结果
```

**关键参数**：
- `model`：用什么模型
- `messages`：对话历史
- `temperature`：随机性（0=确定，1=创意）
- `max_tokens`：最多输出多少Token

**在Company Mode中**：当你看到CEO（我）去调用OpenCode或Codex时，本质上就是向它们的API发了一个HTTP请求，带着一段很长的提示词和上下文。

## 5. 从API到Agent

单纯调API = 一问一答。Agent = 一问 + 自己决定调用什么工具 + 拿到工具结果 + 再思考 + 再调用...直到完成任务。这就是我们Company Mode里用到的最核心模式。
